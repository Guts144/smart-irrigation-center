Smart Irrigation IoT System: Technical Report

1. System Architecture Overview

The project follows a modern MVC (Model-View-Controller) architecture integrated with the Singleton Pattern for resource management. The communication is handled via MQTT (Message Queuing Telemetry Transport), a lightweight protocol ideal for IoT.

Key Design Patterns Used:

  • Singleton: Used in MqttService to ensure only one active connection exists.
  • DAO (Data Access Object): Separates the database logic from the business logic.
  • Observer: Used for real-time UI updates when new sensor data arrives.

2. Core Communications: MqttService.java

This is the heart of the application. It manages the connection to the HiveMQ Cloud Broker and handles incoming telemetry from the ESP32.

// Singleton implementation
public static synchronized MqttService getInstance() {
    if (instance == null) {
        instance = new MqttService();
    }
    return instance;
}

Mechanism: When a message is received on the irrigation/device/+/telemetry topic, the service parses the JSON payload using GSON and triggers a callback to update the UI.

3. Data Persistence: DatabaseManager.java

We use SQLite for data storage. The DatabaseManager class handles the creation of tables and ensures query performance through indexing.

Table Name Purpose
sensor_data Stores historical Temperature, Humidity, and Moisture readings.
users Stores encrypted credentials and role-based permissions (Admin/User).
valve_history Audit log of every time the irrigation valve was opened/closed.

Optimization: We added a busy_timeout=10000 to the JDBC URL to prevent database locks during high-frequency sensor updates.

4. IoT Firmware: ESP32 sketch.ino

The field device logic is written in C++ for the ESP32. It acts as the data source for the entire ecosystem.

// Sensor Reading & JSON Serialization
void loop() {
    float h = dht.readHumidity();
    float t = dht.readTemperature();
    int soilRaw = analogRead(POTPIN);
    // Publish JSON payload to MQTT every 5 seconds
    String payload = "{\"temperature\": " + String(t) + "}";
    client.publish(topic, payload.c_str());
}

Architecture: Using PubSubClient for MQTT and WiFiClientSecure with setInsecure() to handle TLS-encrypted cloud communication without requiring complex certificate bundles in a simulation environment.

5. Intelligent Automation Logic

The system doesn't just display data; it makes decisions. In HomeViewController.java, a dedicated method checks thresholds every time a new reading arrives.

// Automatic Logic Implementation
private void checkThresholdsAndAutomate(SensorData data) {
    // 1. Fire Safety
    if (data.getTemperature() > 60) {
        showFireAlert();
        mqttService.publishValveCommand("VALVE_ON");
    }
    // 2. Drought Prevention
    if (data.getSoilMoisture() < 20) {
        mqttService.publishValveCommand("VALVE_ON");
    }
}

6. Real-Time Visualization

The ChartsController uses JavaFX AreaChart and LineChart to plot sensor data over time. Because UI updates in JavaFX must happen on the Main Thread, we use Platform.runLater() to synchronize the background MQTT threads with the graphical interface.

7. Conclusion

This project successfully integrates Embedded Systems (ESP32), Cloud Networking (MQTT), and Modern Software Engineering (JavaFX/SQLite). It provides a high-fidelity solution for precision agriculture with a focus on safety, performance, and user experience.
